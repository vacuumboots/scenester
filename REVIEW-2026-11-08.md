# Scenester — full review, 2026-11-08

Three independent reviewers (frontend, backend, build/CI/docs) plus a
line-by-line read of `main.py` and `plex.py`, each claim re-checked against the
running container before it was believed. Anything a reviewer claimed and I
could not reproduce is listed under **Disproved**.

Fixed here is everything that was both real and safe to change in one pass.
What was real but needs a maintenance window is in **Open**, with the exact
steps, so the next session does not have to re-derive them.

Verification for this pass: **80 tests pass** (16 new), live export through
`/scenester/` renders 12.0s / yuv420p / no chapters, `/healthz` green,
mark-edge behaviour driven in a real browser.

## Fixed — correctness (wrong output shipped silently)

### A failed encode used to poison its filename permanently
`create_clip` treated **existence** as completion, and ffmpeg wrote straight to
the served name. An interrupted encode (redeploy, OOM, power cut) left a file
that exists, has bytes, and no player can open — and every later POST for that
range answered `ready`, so the range could never be re-exported without
deleting the clip by hand.

Now: encodes write `<name>.part`, are verified with `ffprobe` (positive
duration — a moov-less MP4 fails), and are `os.replace`d into place only then.
`create_clip` probes an existing file instead of trusting it, and deletes it if
unplayable. Abandoned `.part` files are pruned at boot. Proven by unit test and
by a live export (`Possible_Love_2026_61865_9020.0-9032.0.mp4`, 12.01s).

### Clip filenames collided across different films
`_slugify` stripped everything outside `[a-zA-Z0-9 _-]` and the basename had no
year or id, while the clip cache is keyed on the filename. Measured: `東京物語`
and `砂の女` both slugged to `unknown`; the library holds **12 slugs shared by
more than one film** (`Mother` ×3, `Bottle Rocket` ×2, `Eureka` ×2).

Now: unicode-safe slug, year, and media id — `Title_Year_ID_start-end`. The id
is the only true unique key because duplicate copies share title *and* year.

### Every export failed once the `.part` scheme landed
ffmpeg infers its muxer from the output extension and cannot map `.mp4.part`
("exited with code 234: Invalid argument"). Caught by testing the live export;
both paths now pass an explicit `-f mp4` / `-f gif`. Worth recording because it
would have broken **all** clips, and the new error surfacing is what made it
legible in one line.

### Quote search blocked the whole app
The index *build* was moved off the event loop earlier; the **search** was not.
Every `/api/quotes` request scanned ~1.2M subtitle lines synchronously in the
single uvicorn worker, so any query stalled every other request including an
in-flight video stream. Now runs in a worker thread, and queries under two
characters are refused outright (`q=e` matched everything and cost a full scan).

### Ranges were never checked against the real runtime
`_check_clip_range` only tested `end - start`. `start_sec = -5`, or an end past
EOF, was accepted: ffmpeg exits 0 having written fewer frames, and the result
was cached under a filename claiming the requested range. `NaN` also passed
(`nan <= 0` and `nan < 0.5` are both False) and became `Title_nan-nan.mp4`
with `-ss nan`. Now `Field(ge=0, allow_inf_nan=False)`, start validated against
Plex's duration, end clamped to it.

### Caption options could reach the filesystem and the filtergraph
`caption_color` / `caption_position` were free strings concatenated into the
output filename and the `subtitles=…:force_style='…'` argument. A value
containing `/` produced a path outside `CLIPS_DIR` (contained only because
ffmpeg then failed). Now `Literal` enums; `words_per_chunk` bounded 1–20.

### Nothing had a timeout
Neither frame extraction nor encoding had a deadline. Both semaphores hold 2
slots, so two wedged ffmpeg processes (corrupt file, stalled mount) disabled the
film strip and all exports until a restart, with the client polling `done:false`
for its full 10 minutes. Frames now time out at 25s and are killed; encodes at
`max(180s, 20×duration)` and report `encode timed out after Ns`.

### The codec probe blocked the event loop
`subprocess.run()` inside an async path — measured 0.34s on a warm 3.3 GB file,
worse cold or while Plex reads the same spindle, and repeated per clip. Now off
the loop and memoised per `(path, mtime, size)`.

### Encoding tasks were untracked
`create_task` results were dropped, so shutdown cancelled nothing and left
ffmpeg children running. Tasks are tracked; the lifespan cancels **and awaits**
them (the old code cancelled without awaiting, which is the "Task was destroyed
but it is pending" path).

## Fixed — UI state (wrong range, lost work, tiny targets)

| Bug | Effect |
|---|---|
| `mobMarkEndAt` pinned the start unconditionally | One tap of Set End armed a clip from **0:00** to the playhead and froze the range — the documented "start rides the playhead" mode was unreachable |
| `mobMarkStartAt` cleared a pinned end unconditionally | Mark End, then Set Start to trim the head: the explicit OUT was discarded and the range grew to wherever the playhead went next |
| Download armed on one marked edge | `updateTimeDisplay` widens a single-mark seed to 1.0s, above the 0.5s floor, so Set Start alone enabled a 1s junk clip. Now requires **both** edges |
| `downloadClip` had no re-entrancy guard | Enter bypassed the disabled button; two runs shared one poll handle, and whichever settled first cleared the other's timer — the second export vanished with no error |
| `downloadClip` skipped the UI's own range predicate | Enter could post a sub-0.5s range and surface the backend's 400 as a raw error string |
| Arrow keys moved the range without pinning it | The follow driver re-centred it, so keys appeared to do nothing and left a hidden range Enter could export |
| Caption lines carried over between films | Until the next film's metadata loaded the Lines panel still listed the **previous** film's dialogue, and tapping a line marked that film's timestamps |
| Delete was a 22×20px ✕ beside Download, no confirm | For a user with radial nerve palsy this is the exact precision aim to avoid, and a miss destroys an export. Now 44px, `aria-label`d, and two-step ("Delete?" → tap again within 4s) |
| `deleteClip` ignored the HTTP result | A rejected delete looked identical to a success |
| Failed detail fetch did nothing | Tapping a dead card left the screen unchanged and invited repeated taps |
| Nudge fired a cold ffmpeg seek per tap | Each nudge is a new `/api/frame` cache key; holding the button buried the spindles. Snapshots now debounce 500ms |
| Double-tap Connect leaked a poll | Two PINs created, first interval unkillable |
| Service worker wrote its cache unawaited | `respondWith` only keeps the worker alive until the response resolves, so the offline shell could silently diverge |

Cache-buster bumped to `?v=76`; a hard refresh is needed on the phone.

## Fixed — build, deploy, CI

- **`:prev` was tagged from `:latest` before the build**, so a failed deploy
  left `:latest` on the broken image and the *next* deploy saved that as
  `:prev` — the rollback target rotted to exactly the thing you needed to roll
  back from. Now `:prev` comes from the running container's image, and a failed
  deploy restores `:latest` before exiting.
- **Preflight** before touching the live container: warns if
  `/dev/dri/renderD128` is gone, aborts if port 8096 is held by something else.
- **`/healthz`** replaces the old probe. `/` is a static file and
  `/api/auth/status` is an in-memory boolean — both stayed 200 with Plex
  unreachable, `/media` unmounted, `/data` unwritable or ffmpeg missing. The
  new probe checks cache writability, the cache-fallback flag, `ffmpeg`/
  `ffprobe` on PATH, and `/media`; it returns 503 with the reasons.
  `deploy.sh`, the Dockerfile HEALTHCHECK and CI all use it.
- **Resource limits**: `--memory=3g --cpus=3 --pids-limit=512 --init`. On a
  4-core/7 GB box shared with Plex, soulsync and slskd there were none at all.
- **CI now gates publishing**: `docker-publish` has its own `test` job and
  `build.needs: test` — previously a red pytest run still overwrote `:latest`.
  `workflow_dispatch` can no longer push (it could publish any branch as
  `:latest`). CI also **runs** the image and polls `/healthz`, because every
  failure that matters (wrong CMD, missing static, absent ffmpeg) happens after
  a successful build.
- `.pytest_cache/` added to `.gitignore`; `PYTHONUNBUFFERED`,
  `PYTHONDONTWRITEBYTECODE` and OCI labels added.

## Open — real, not done here

### 1. The API is unauthenticated and the port is published on 0.0.0.0 (highest priority)
`-p 8096:8096` binds every interface. Anything on the LAN can stream the whole
library, list and delete clips, and keep both encode slots busy. The `:ro`
media mount caps the damage to disclosure plus DoS.

The fix is not a one-liner: Caddy currently dials `host.docker.internal:8096`
(the published port), so simply binding the port to loopback breaks
`/scenester/`. Plan: attach Caddy to `hms_media_net`, change the Scenester
route to `reverse_proxy scenester:8096`, drop `-p 8096:8096`, and switch
`deploy.sh`'s health probe to `docker exec … /healthz`. Do it in one window and
verify every other Caddy route afterwards.

Second layer, independent of the network change: a shared-secret middleware
(`SCENESTER_ACCESS_TOKEN` with `hmac.compare_digest`) on `/api/*` except
`/api/auth/*`, plus the PIN-flow binding fix (any reachable client can
currently create a PIN, approve it with its own account and overwrite the
stored token).

### 2. Runs as root with `/dev/dri` and a media mount, no capability drop
Deferred because it needs `chown -R` of `CLIPS_DIR` and `/data` on the host
(the container has already written root-owned cache files — removing the
preview container's temp dirs required a privileged chroot). Steps: wrap
`CLIPS_DIR.mkdir` (done), add a `scenester` user, chown `/app`, `/tmp/clips`,
`/data`, run with `--user`, add `--cap-drop=ALL --security-opt=no-new-privileges`
and add the user to the host `render` group.

### 3. Nothing is pinned
Base images are floating tags, `apt-get install ffmpeg` is unpinned, and
`requirements.txt` has four `>=` ranges with no lock. This matters here
specifically: the VAAPI green-frame fix depends on filter-graph negotiation in
a specific ffmpeg build. Pin base images by digest, pin the apt layer, and
compile a hashed lockfile.

### 4. Quick Clip's poll is still uncancellable
Same defect class that was fixed for the export path; a Quick Clip abandoned
mid-encode still downloads up to 10 minutes later.

### 5. Multi-part films only work in part 1
`_translate_path` returns one `Part` while the timeline uses the full runtime.
8 items in this library are affected — `La Flor` (8 parts), `Gilles Deleuze
from A to Z` (5), `Leviathan`, `At the First Breath of Wind`, `Mezzo Forte`.
Clips past part 1 seek past EOF.

### 6. Only `.srt` subtitles are read
1 directory has `.ass`/`.ssa` only and 496 have no subtitle file at all
(~26% of titles), so captions are unavailable there.

### 7. Documentation
`.env.example` documents 3 of ~12 settings; `SCENESTER_FRAME_CONCURRENCY` — the
lever for the documented load spike — is undiscoverable, and the README has no
configuration table.

### 8. A live API key sits in the working tree
`gitignore_human_handoff/soulsync_api_key.txt` is a real SoulSync token. It is
gitignored, was never committed (`git log --all -- <path>` is empty) and never
reached the image, so it has not leaked through git. It was world-readable and
travels with any rsync of the repo; it is now `0600` and **should be rotated
and removed**. `.pytest_cache` was the only genuinely stageable junk.

## Disproved

- **gzip middleware does not break range requests.** `Range: bytes=0-1023` with
  `Accept-Encoding: gzip` returns 206, `Content-Range`, `Content-Length: 1024`,
  and no `Content-Encoding`.
- **The publish workflow does fire on `main`** — the repo is on `main`, not the
  `master` the old plan documents claim.
